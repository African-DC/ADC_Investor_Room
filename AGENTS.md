# Règles ADC
Lire README et docs avant toute modification, ainsi que l'issue active. Branches feat/E##, PR vers main, pas de merge automatique ni force push, pas de déploiement production. TypeScript strict, TanStack Start, React, Tailwind/shadcn, Convex + Better Auth, Resend, Convex File Storage (no R2). Lockfile reproductible après vérification. Zod aux frontières.
Refus par défaut, identité serveur, ACL par room/section/document et capacité, expiration/révocation, deny prioritaire, NDA versionné. Ne jamais croire les rôles du client. Aucun secret, pièce réelle, URL de stockage publique, PII dans logs ou preview. MFA admin avant production. SSR protégé, no-store, noindex, tests négatifs.
UX premium fidèle à ADC, FR/EN, mobile/desktop, clavier, reduced motion, états chargement/vide/erreur. Pas de faux succès ni chiffre inventé. Nom et e-mail seuls obligatoires; autres champs facultatifs. CMS brouillon/revue/publié/archivé. Séparer facturé, encaissé, CA comptable et ARR; relier aux preuves, pas de faux justificatif. Notes CRM privées.
Definition of Done: critères de l'issue, lint, typecheck, tests, build réellement exécutés; tests inter-room et révocation, accessibilité, documentation et PR avec preuves et limites. Ne pas clore un ticket sur code non testé.
## Vercel UI SDK
Utiliser @ui-sdk/react et @ui-sdk/core (bêta épinglée) pour les interactions accessibles, avec styles ADC. Avant utilisation, suivre le skill ui-sdk s'il est installé et lire node_modules/@ui-sdk/react/docs/llms.txt; pour un nouveau composant, consulter core.md et rendering.md. Installation optionnelle du skill dans un agent local: npx skills@latest add vercel-labs/ui --skill ui-sdk. Ne jamais connecter le bridge agent/WebMCP à la Data Room ni permettre de contourner les permissions. Tests clavier, SSR et focus; pas de mise à jour bêta automatique.
