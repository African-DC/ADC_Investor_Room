# E05–E07 — protected portal and staging-only content operations
No production deployment or data. ADC_PORTAL_ENABLED defaults false at the TanStack server; both prior auth flags and real provider config must be set in isolated staging. Convex independently validates verified identity, published room, explicit room and section grants, denial priority, expiry/revocation, NDA acceptance for current version, and exact published revision. Room labels are visible only with explicit room permission; NDA text is shown before content. Search filters only authorized sections already returned (not a full-text index). Bounded queries fail closed above 200 grants / 100 sections / 100 NDA acceptances; add pagination before large-scale rollout. No client role, no automatic grant.
Investor UI uses no-store responses and refetches every 30s and on focus; revocation is enforced at the next server request, already seen content cannot be recalled. Real authenticated/revocation tests still required.
## Operator workflow in isolated development
Enable ADC_STAGING_CMS=true ONLY in a dedicated Convex staging deployment. Internal mutations are not public APIs. Use trusted CLI/dashboard operator; supplied operatorId is an asserted staging audit label, not proof of separate authenticated reviewers. No production admin UI or MFA yet.
1. createRoom, setRoomStatus; optional setNda with unique immutable version.
2. draft bilingual section with source and author label; submit as author; publish with distinct reviewer label. Previous published revision stays live while new draft/review exists. archive hides content. Restore workflow pending.
3. grant room:read and section:read separately to verified authUserId, optionally a specific section and expiry; revoke by grant ID. No grant automatically issued.
4. Login as investor, select room, accept NDA if applicable, view/search authorized content.
Do not enable ADC_STAGING_CMS in production. Never use real investor data during staging. MFA-bound administrative identity, role assignment, admin UI, durable audit retention, signed NDA evidence policy and actual end-to-end provisioning remain release blockers. Documents/R2 and financial source-backed publishing remain separate epics. No actual business content seeded.

Independent Convex kill switch ADC_CONVEX_PORTAL_ENABLED defaults off. Both server and Convex portal flags must be enabled in isolated staging. DB tests use convex-test with synthetic fixtures and server-only identity helper; these do not replace live Better Auth or MFA tests. The NDA checkbox is tied to the exact displayed version; overlapping refreshes discard stale responses.

## Back-office staging (E07)
ADC_STAGING_ADMIN_UI=true on both server and Convex, ADC_STAGING_CMS=true on isolated synthetic development only. Admin membership is assigned by trusted CLI internal admin:provision with verified Better Auth user ID, room ID and explicit capabilities; admin:revokeMembership disables access; admin:assignApplicant explicitly associates a verified profile with a room. No role is accepted from browser. Admin public wrappers derive operator ID from verified auth, check scope and capability in the same transaction, call internal CMS mutations, enforce separate actual user IDs on submit/publish. No automatic provisioning or access to unrelated applicants. No production admin before real MFA. UI includes room selection, applicants/access management, editor and preview, publication, archive, and document metadata and scoped grants (upload disabled). Room creation, NDA configuration and applicant assignment still CLI-only; history/rollback and document storage pending. Admin screen FR only currently. Bounded lists fail closed; pagination remains. Real auth and mutation E2E pending.
