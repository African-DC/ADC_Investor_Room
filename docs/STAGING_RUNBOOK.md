# ADC Investor Room — staging runbook
No production deployment or secrets committed. Start from the reviewed PR SHA, not main.
1. Set up a dedicated ADC Convex development deployment. Run the real Convex CLI codegen and compare generated bindings with bootstrap declarations. Run unit tests and build. Set SITE_URL to the exact staging app origin; set Better Auth secret and Resend verified sender. Keep all feature flags false initially.
2. Create Vercel preview project scoped to ADC. Configure VITE_CONVEX_URL and VITE_CONVEX_SITE_URL for the development deployment only, ADC_APP_ORIGIN equal to exact URL, ADC_AUTH_ENABLED and VITE_ADC_AUTH_ENABLED after configuration. Do not reuse production secrets; disable link tracking for login email.
3. Validate magic link with controlled inboxes: token once, expiry, confirm route, session revocation, invalid origin, no fake send. Then turn on both portal flags in staging.
4. Use trusted internal stagingCms:createRoom, stagingCms:setRoomStatus, admin:provision, admin:assignApplicant with actual verified identity IDs (not emails). Use two independently controlled test admin identities, separate reviewer, and an investor. Enable ADC_STAGING_CMS and ADC_STAGING_ADMIN_UI only in isolated development; never in production. No real data at this stage.
5. Use Convex File Storage with random independent shared upload/delivery secrets on server and Convex. No R2 account needed. Verify the generated upload URL origin and /adc/storage/read ticket route with synthetic files. External malware scanner must verify exact SHA-256 before marking clean. Upload a synthetic PDF, publish with separate reviewer, grant exact read/download, revoke, archive and verify financial projection disappears. Test across rooms and direct document IDs.
6. Enable each pair of feature flags individually (finance, Q&A, analytics, AI), verify exact authorization including negative cases, consent and purge. For technical reporting use least-privilege GitHub read-only token and exact room allowlist. For AI begin local; no external processing until ADC approves exact data classification, provider terms and source versions. No personal data or real investor records during staging.
7. Record exact commit SHA, test actor IDs (not passwords/tokens), expected/actual results, provider project IDs, defect owner and decision. Keep MFA, live scanner, real provider tests, dependency review, backups and content reconciliation as mandatory gates. Do not merge/deploy based on code coverage alone.
8. Before any production release, require session-bound admin MFA, security review and human release approval; remove staging-only admin flags. Never reuse staging CMS operator-label shortcuts in production.
