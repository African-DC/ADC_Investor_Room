## Invitation, OTP and session hardening
Admin magic-link callbacks both target /admin. Verified email claims only exact live invitation, then session-bound MFA. Sign-in offers email link (15 min) or six-digit email OTP (10 min, 5 attempts, hashed). Email OTP is a first factor, not a substitute for Authenticator. Admin loader displays explicit signin/membership/temporary error instead of redirecting on every failure. MFA proof renews only on explicit visible trusted UI activity, throttled 60s, defaults 120 min idle, absolute 24h. Convex env ADC_ADMIN_IDLE_MINUTES (15–480), ADC_SESSION_TTL_SECONDS (3600–604800, default 86400), ADC_SESSION_REFRESH_SECONDS (60–900, default 300). No background renewal of MFA. Existing proofs may need one re-verification; optional schema compatible. Live test new/existing invite, both methods, wrong/expired invite, TOTP, no membership, auth refresh and temporary 429/503. Verify actual cookie renewal. UI activity is not proof of human presence against compromised client; server expiry authoritative. No live provider setup.
